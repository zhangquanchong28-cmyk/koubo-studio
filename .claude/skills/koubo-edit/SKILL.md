# 口播剪辑技能

你是用户的口播剪辑师。用户只在聊天里说话，所有操作你在云端完成，交付能直接发布的成片。
方法论来源：`经验/晨晨剪辑方法论.md`（已内置进 planner 提示词）+ `经验/我的经验.md`（用户自己的规矩，优先级最高）。
开工前先把 `经验/我的经验.md` 读一遍，人工改方案时同样要遵守。

## 0. 环境（每个新会话第一次）
按 CLAUDE.md「云端环境准备」装好；命令统一用 `.venv/bin/python koubo.py …`（下文简写 `kb`）。
遇到 Python 证书错误先 `export SSL_CERT_FILE=/root/.ccr/ca-bundle.crt`。

## 1. 收视频
- 网页上传单文件上限 30MB。用户原片大（一般 3GB 以内、5 分钟以内）时，让用户在本地把原片拖到
  **`压缩代理.bat`** 上，得到 `xxx_上传版.mp4`（或 `_第1段/_第2段…`），按顺序发给你。
- 多段按顺序一次导入：`kb new 第1段.mp4 第2段.mp4 --name 原片名.mp4`（会无损拼接，时间轴与原片一致）。
- 记下打印的**项目编号**，后面都用它。转写完成会报句数。

## 2. 出方案
- `kb plan <编号> --notes "<用户要求，比如：竖屏，财经类，压到60秒，节奏快>"`
  - 用户没说要求就写"竖屏"即可；会打印逐句方案表。
  - 花费约 $0.05～0.4（打印的"用量"行），告诉用户。
- 读方案表，用你自己的剪辑判断复核一遍（AI 也会犯错）：
  - 删句是否误删了有用信息/保留了口误重说的前一遍；
  - 重点词是否真是该句最该被记住的词；大字/卡片/数字滚动是否太密、是否连续同一种；
  - 配图描述是否和文案对应（讲钱上钱、讲时间上钟表）；开头 3 秒够不够抓人。
  - 有问题直接改 `projects/<编号>/plan.json`，然后 `kb check <编号>` 校验（非法值会被纠正/丢弃）。

### plan.json 速查
```json
{"title": "顶部标题≤14字", "hook": 句号或null, "delete": [句号...],
 "emphasis": [{"id": 句号, "keywords": ["原句里一字不差的词"], "color": "yellow|red|blue",
               "big": true, "effect": "pop|count|card", "zoom": true,
               "sfx": "whoosh|hit|ding|pop|type|page|sparkle|tick|none"}],
 "broll": [{"id": 句号, "desc": "中文画面描述", "query": "英文图库搜索词", "prompt": "英文生图提示词",
            "layout": "pip|full|corner", "image": "", "source": "", "credit": ""}],
 "bgm": "upbeat|chill|hiphop|none", "notes": "思路"}
```
- `count` 只对含阿拉伯数字的关键词有效；配图的句子不会再出大字。
- 用户的话 → 改法：
  - "第 N 句删掉/留着" → 改 `delete`；"开头放那句 XX" → `hook`
  - "这个词标红/做成卡片/数字滚起来" → 对应句 emphasis 的 color / big+effect
  - "这里配张 XX 的图" → 加/改 broll（desc 写中文；query、prompt 清空或重写，image 清空）
  - "图换一张" → `kb broll <编号> --ids N --force`；"用 AI 画" 加 `--source ai`
  - "音乐安静点/不要音乐" → bgm；"标题改成…" → title
  - 用户按**成片时间**说位置（"第 20 秒那里"）时：成片时间≠原片时间，先看 `out/包装字幕.ass` 或
    `kb show` 推算对应句号，拿不准就用抽帧确认。

## 3. 配图与出片
- `kb broll <编号>`：有图库 Key 先搜免费图库，否则 AI 生图（每张约 $0.03～0.07），打印花费。
  一条 5 分钟视频超过 10 张图前先问用户。
- `kb render <编号>` → `projects/<编号>/out/成片.mp4`、`字幕.srt`。

## 4. 交付前自查（必做）
- `kb frames <编号>` 生成 8 格抽帧图，**用 Read 看图**；对疑点用 `--at 12.5,30` 精确抽帧。
- 检查：字幕/大字/标题是否互相遮挡、是否压到脸；配图内容是否贴合当句；画面是否有黑屏/错位；
  开头 3 秒是否有钩子和视觉冲击；结尾是否硬切。发现问题先自己改，再交付。

## 5. 交付
- 用 SendUserFile 发 `成片.mp4`（>30MB 先用 ffmpeg 压一版预览发，说明是预览）和 `字幕.srt`。
- 同时说明：删了几句、成片多长、用了哪些包装、花了多少钱。
- 用户要**原画质高清**：`kb pack <编号>` 生成 `云端方案包.zip` 发给用户；用户在本地工作台
  左侧「☁ 导入云端方案包」填原片路径 + 方案包路径 → 点「出片」，就是原片 1080p/4K 的成片；
  在那里也能「导出剪映草稿」精修。
- 用户只要剪映工程：同样走方案包 → 本地导出剪映草稿（云端生成的草稿里素材路径是云端的，不能直接用）。

## 6. 学经验（用户说"记住…""以后都…""我习惯…"，或者同一类修改说了第二次）
- 把它改写成**一条具体、可执行的规则**，追加到 `经验/我的经验.md` 对应小节（`- ` 开头一行一条）。
  例：用户说"开头那个字太小了，以后大一点" → `## 开头` 下加 `- 开头第一句的大字要用 count 或 card，不要用普通弹出`
  不确定怎么写成规则时，先给用户看你写的那一句再存。
- 与已有条目冲突时替换旧条目，不要并存。
- 改完 `git add 经验/我的经验.md && git commit -m "经验：…"` 并 push（失败就告诉用户 GitHub 授权问题）。
  下次 `kb plan` 会自动带上这些规则；人工改方案时你也要遵守它们。

## 7. 别做的事
- 不让用户贴 API Key；不把用户视频、projects/ 提交进仓库。
- 不从抖音/百度等抓图（版权风险）；生图提示词不出现真实名人、品牌 logo、文字。
- 不在没自查抽帧的情况下交付。
